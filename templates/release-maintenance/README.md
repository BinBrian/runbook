# 维护工作演示

[maintenance.runbook.json](maintenance.runbook.json) 展示“维护演示 · 发布与玩家转区”：包含参数填写、独立步骤组、命令复制和人工记录。环境、区服、玩家、平台账号及人员称呼均为虚构演示数据；命令只是演示文本，不是实际业务操作指引。文件不携带执行结果或用户数据。[source.txt](source.txt) 是同一份演示流程的纯文本校验基线。

1. 在 Runbook 点击“导入”，选择 JSON 并确认，生成一份未开始的工作记录。
2. 在右侧变量栏填写维护起止时间（`YYYY-MM-DD-HH-mm`），核对其他参数。演示时间不作为默认值自动带入。
3. 全局环境为 `release`；维护预告组共享起止时间；发布来源分支是步骤局部参数，默认为 `preview`。三个玩家组分别拥有区服、玩家和平台账号参数，六条命令与通知共用各自的组内值；通知只引用玩家 ID。
4. 按需调整流程；不需要的转区组可在开始前删除。开始后，按顺序人工记录完成、失败或跳过，评论和图片保存在这份工作中。
5. “示例环境A sandboxa · 更新重启”包含停止、发布、同步和启动四个子步骤，使用组内环境 `sandboxa`，与全局环境独立。
6. 后续在工作记录上点击“再做一次”，创建可独立调整的新工作；原记录的结果、评论和图片留在原处。

文件沿用历史清单格式 `formatVersion=2`、`kind=template`，当前产品将它导入为工作记录，并没有独立模板页签。共 46 步、32 条命令、14 个人工检查点、5 个步骤组和 17 个参数。`source.txt` 提供 28 条基础演示命令，生成脚本补入 4 条环境重启演示命令。`transferserver env` 是参数用法说明，不是可复制步骤。

复用定义与四环境示例见[收藏步骤示例](../../docs/examples/blocks/README.md)。在仓库根目录运行 `python scripts/generate-scoped-examples.py` 可重新生成示例并检查命令顺序；脚本只更新仓库示例，不访问用户数据库，也不执行命令。重新导入时可选择独立副本。

截图、通知、日志检查、邮件、合服和内部测试环境更新使用人工记录。维护邮件发送完成单独确认后，最后一步才是开放登录；应用仅记录结果和复制文本。
