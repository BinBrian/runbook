# ADR 0010：一体化窗口标题栏

状态：2026 年 10 月 20 日已实现并通过真实窗口验证。复用工作区 Runbook 规划。

## 问题

独立 Windows 标题条与应用面包屑顶栏重复占用空间，浅色系统条将窗口外壳与深色侧栏、浅色正文割开。用户要求参考 VS Code，把标题与应用内容合为一体。

## 决策

主窗口关闭系统 decorations，保留 resizable 与 shadow；应用沿用现有顶栏承载面包屑、保存状态、导入和原生窗口控制，不新增标题行。左侧栏保留深色背景到窗口顶边，其顶部空白与应用顶栏都提供原生拖动区域。

按本项目已安装 Tauri 的拖动注入实现，顶栏使用 `data-tauri-drag-region="deep"`，操作区明确设为 false；原生注入处理拖动和 Windows 双击最大化，不另写重复双击处理器。按钮和输入不得成为拖动目标。

窗口操作只开放 close、minimize、toggle-maximize、start-dragging 四项必要权限，查询和 resize 事件使用已有 core 权限。最大化状态跟随实际窗口查询与 resize 事件，组件卸载释放监听，迟到的订阅立即清理。

关闭按钮只发送正常 close 请求，统一刷新编辑缓冲并保存本机显式草稿后退出，处理注册完成前按钮不可用。不能在标题栏直接调用 destroy 或跳过保存。2026 年 10 月 21 日用户取消未提交输入阻止关闭的旧规则，真实保存失败的选择与草稿恢复见 [ADR 0012](0012-local-drafts-and-close.md)。弹窗遮罩不能挡住窗口控制。原有下方验收记录描述旧版行为，不作为当前关闭要求。

## 验证与限制

隔离真实 EXE 已验证无系统装饰、最大化/还原标签同步、最小化恢复、关闭阻止未提交评论、关闭刷新待保存编辑并正常退出，以及小窗口与既有导航布局。测试恢复最小化窗口只操作自己创建的 PID，不为测试额外开放应用能力。126 项前端测试、类型检查及独立桌面构建通过；证据和隔离目录见[验证记录](../testing.md)。

原生鼠标拖动、贴边停靠与 Windows 系统菜单的完整行为另作人工验收，不用 DOM 属性检查宣称已经实际拖动或验证所有系统壳交互。用户数据不参与测试。
