# ADR 0013：工作记录本身就是复用起点

状态：2026 年 10 月 21 日实现，隔离验证通过，桌面更新状态见[验证记录](../testing.md)。替代 ADR 0008 中独立模板阶层的产品设计，不改变人工记录和冻结边界。

## 决策

取消独立模板模块。用户直接新建工作，或在选中的已有工作上点“再做一次”。待开始、进行中、已完成、已终止及归档工作都可作为原型，来源只保留为追溯标识，后续编辑不传播。

| 内容 | 再做一次 |
| --- | --- |
| 步骤、组、说明、命令、变量定义及默认值 | 完整独立复制，可继续编辑 |
| 已应用参数值 | 默认带入供核对；可取消勾选，改用定义默认值 |
| UI 未应用参数草稿 | 不作为新工作的已应用值，保留在原工作 |
| 状态、当前步骤 | 新工作 draft，显式开始后从第一步记录 |
| 结果、快照、评论、图片、操作时间、终止原因、归档 | 不继承，留在原工作 |

每份工作既能记录实际操作，也能成为另一份工作的起点。主导航为工作记录、步骤块、归档。步骤块继续是可插入的内容工具，不成为工作创建前提。没有“另存为模板”或回写来源的操作。

## 实现与已有内容

现有 instance 存档结构完整表达工作与历史，保留该内部契约；新增 create_work 与 repeat_work 用例，不要求为创建工作先创建 template。完整存档仍为包含 runbook.json 与图片的 .runbook.zip，导入历史保留原进度，与“再做一次”清空执行记录的行为分开。

应用使用 checklist_load_work。存在旧清单模板时，将定义与默认值转换为未开始工作；同一 SQLite 事务写入转换前原始工作区与模板到工作 ID 映射，再提交新工作区。原模板 ID 与现有工作冲突时分配新工作 ID，不改已有记录。模板集合转换后为空，反复读取不重复生成，删除转换后的工作也不重新创建。原始备份只用于保留旧数据，不作为产品维护对象。

旧清单模板 JSON 导入为普通未开始工作，重复时仍明确导入独立副本。旧模板表单及名称草稿按身份映射继续编辑，不按显示名称推测；重做选项属于显式草稿，重开后保留。旧原生模板 DTO 与方法保留用于已有清单读取/旧测试，产品界面不调用创建或保存模板。旧 Markdown 数据库不读取、不迁移、不删除。

## 代价与验证

工作区会保存多个独立快照；这是历史隔离所需，用户只维护当前使用的那份。来源删除不能影响其他工作。对原定义的调整不会自动修订既有快照。

测试覆盖事务失败回滚、备份原文、身份冲突、幂等/删除不重建、各状态复用、参数选项、双向隔离、全部历史材料不继承、旧表单草稿恢复、完整 ZIP 导入和正常退出重开。系统文件框、剪贴板与真实用户数据的验证边界见[验证记录](../testing.md)。
