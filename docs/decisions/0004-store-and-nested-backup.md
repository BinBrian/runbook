# 独立仓储、关系列与嵌套备份

状态：已实现。日期：2026 年 10 月 13 日。

本文保留初版 schema 1 的决策背景。参数字段、JSON schema 2、旧库一致性备份与升级规则由 [ADR 0006](0006-parameters-and-independent-instances.md) 补充；当前验证见 [testing.md](../testing.md)。

本决策补充 [ADR 0001](0001-workspace-and-native-core.md) 的仓储位置与持久化表达，保留 [ADR 0002](0002-markdown-and-stable-identity.md) 的 Markdown 权威和 [ADR 0003](0003-run-snapshots-and-attempt-history.md) 的历史规则。

## 背景

实施需要在没有 Tauri 窗口的进程中验证 SQLite 事务、只读历史、幂等重试和恢复。把业务与仓储都放在桌面壳会使这些测试耦合窗口依赖。全部 DTO 字段都映射成列增加首版维护量，而整个工作区只存一行 JSON 又失去外键和单步骤草稿约束。

## 决定

1. 新增 native/runbook-store，统一 Request/Action、用例、revision、幂等回执、SQLite 和备份。runbook-core 保持纯语义，Tauri 壳负责 IPC、应用目录、窗口和文件交互。
2. 保留模板、实例、步骤、轮次、注释关系表。主键、外键、排序与约束使用列，其余业务数据序列化为每实体 payload；父 payload 清空子数组，读取时重建关系。
3. JSON schema 1 为 Backup { format, schema_version, exported_at, templates, runs }。实例内嵌步骤，步骤内嵌轮次，轮次内嵌注释，携带已移除步骤和全部历史。导入重新解析、校验并分配新实体 ID。
4. Tauri 固定 perform 命令接受带 type 的 Action 联合类型，不接受任意 SQL。模型与操作类型分别由两个 Rust 生成器输出 TypeScript。

## 备选与代价

| 方案 | 取舍 |
| --- | --- |
| 仓储留在 src-tauri | crate 较少，但数据库测试与桌面依赖混合，本版拆出 |
| 每个业务字段独立成列 | SQL 与迁移更显式，首版映射较多；需要特定查询时再提取字段 |
| 单一工作区 JSON 行 | 代码少，缺少细粒度外键、轮次唯一与单 draft 约束，未采用 |
| 关系列加每实体 payload | 保留结构约束与 Rust DTO 表达，采用；payload 变化仍需版本设计 |
| 顶层扁平备份数组 | 关系导出直接，但导入需重新拼接全部关联，改用完整嵌套对象 |

嵌套数据仍需严格校验：当前步骤匹配有效原文，历史快照按自身正文验证，同版本指令保持一致。重复的身份字段只能由仓储同步写入，不能在外部编辑数据库。旧设计的扁平 schema 1 尚未发布，本版没有兼容适配器。

## 当前限制与后续条件

- 只有 schema 1 的事务初始化和高版本拒绝，尚无旧库升级或迁移前备份。首次发布后的结构变更须先补旧库样本、SQLite 一致性备份、失败回滚和升级测试。
- 每次保存加载并 upsert 整个工作区，前端和原生均串行写入；没有分页或增量仓储，大规模历史性能待实际容量验证。
- JSON 界面导出整个工作区，没有对象选择备份。导入上限 32 MiB，导出尚未统一容量上限；扩大规模前需统一预检、正式导入、导出范围及容量策略。
- 内部回执不导出，导入来源元数据不作为恢复业务字段；导入创建新的实体身份和本次回执。
- Markdown 标记与 JSON schema 均为 1，没有独立持久化 parser_version。修改解析语义前须制定版本与历史快照兼容策略。

## 验证

核心测试已验证精确指令、假标记、内容版本、草稿保护、更正链及伪造快照拒绝。编辑器测试验证真实 CommentBlock 节点、重复 ID、边界空白和 CRLF。仓储集成测试覆盖事务、幂等、版本冲突和整包恢复；最终 Windows 构建与人工冒烟证据由实施记录维护，本文不代替交付验证。
