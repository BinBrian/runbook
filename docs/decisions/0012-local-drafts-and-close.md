# ADR 0012：本机草稿与正常关闭

状态：2026 年 10 月 21 日实施。复用当前 Runbook 规划。

## 问题与确认

旧版将未提交变量表单、参数及评论当作关闭阻塞项，只显示无位置错误。用户明确要求未提交输入不能阻塞关闭。自动提交又会使参数或人工结果意外生效，因此关闭只保留草稿。

## 决策

正文继续按原原生缓冲自动保存，关闭先刷新。显式输入独立保存为版本化本机草稿，包括变量定义、实例参数、评论/评论编辑、操作名称和原因；按原对象、步骤及动作身份恢复。保存不验证必填业务规则，不应用参数，不写评论、结果或状态。操作仍需用户明确提交，原生引用与冻结规则继续裁决。

使用已配置数据目录下 WebView2 profile 的 localStorage，逐次输入同步写入，正常关闭再次保存。草稿不进入 SQLite 业务记录、模板默认值或 JSON/ZIP；不同数据目录隔离。不读取或迁移旧 Markdown 库。带版本及类型校验；格式无法读取时保留原始存储，不用空列表覆盖，真实写入失败保留当前内存输入并显示状态。

顶栏草稿列表展示所属对象，点击恢复原页面；组内评论展开并聚焦原步骤，变量定义恢复原身份和归属。取消/成功提交仅清除本项，也可以从列表明确丢弃。已推进步骤的旧结果原因草稿不能用于当前步骤，所属对象已不存在时只能丢弃，不按名称重绑。

窗口按钮及 Alt+F4 等正常关闭请求均经过统一保存。未提交输入不弹确认、不阻止退出。只有实际写入失败提供“返回编辑 / 仍然关闭 / 重试并关闭”，明确说明有损选项的影响；显式选择仍然关闭后才跳过失败的保存。窗口控制位于弹窗遮罩上方，任何表单打开时仍可关闭。

## 验证边界

单元测试覆盖身份/原文恢复、目录隔离的独立存储、持久化清理、对象属性顺序、存储失败重试及损坏数据零覆盖；API 测试覆盖保存串行和显式放弃退出。真实桌面使用隔离目录与自有进程，验证多个草稿跨页、正常退出重开、定位与显式提交、500ms 内正文刷新及存储失败选择；证据见[验证记录](../testing.md)。不写用户库、不执行维护命令。
