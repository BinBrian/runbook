# ADR 0008：结构化 JSON 内容与可选 AI 扩展

状态：清单重构已实现，2026 年 10 月 20 日桌面闭环验收通过；AI 扩展尚未接入。确认与实施日期：2026 年 10 月 20 日。

本文记录本轮重新设计与当前实现。用户明确不要求兼容 Markdown 和历史设计；旧产品与子系统文档已归档至 [history/markdown-v0.1](../history/markdown-v0.1/README.md)，ADR 0001–0007 保留历史背景。桌面壳继续沿用显式数据目录与启动诊断，新清单业务独立实现；具体数据与 IPC 字段见[实施契约](../checklist-implementation.md)。

## 背景与目标

用户希望进一步简化交互，并方便后续通过 LLM 生成模板、建议实例参数。本轮采用 JSON，明确不考虑 Markdown 兼容与历史方案兼容。AI 应为后续可选扩展，允许用户自行配置远程服务或本地小模型服务，当前核心编辑和记录功能不依赖模型。

## 已采用的产品选择

- 产品是命令记录与复制辅助工具：展示、记录并一键复制命令，不实际运行命令，不提供终端或自动采集、判断运行结果。步骤完成、失败或跳过由用户手动标记；首版取消独立运行回显区及对应专用字段，需要留档的外部输出统一通过评论和图片记录。
- 从最小业务需求定义 Runbook 自有的结构化内容模型，使用 JSON 表达。编辑器与存储实现按新方案选择，不以复用原有节点、解析器、数据库结构或模块边界为前提。
- 保持操作清单的概念简单：步骤包含标题、说明和零到多条指令；没有指令的步骤可作为人工检查点。用户已确认执行结果的记录单位为步骤，命令不另设独立执行状态；需要逐命令追踪时，将每条命令拆成一个步骤。
- 首版步骤说明使用普通多行文本，命令独立显示为卡片，变量显示为标签，保持内容编辑界面简单。
- 实例执行页默认展开当前步骤，其他步骤折叠显示标题和状态，点击后再展开，保留整个流程的概览；查看或展开其他步骤不改变当前推进位置，编辑权限仍遵循当前、后续和已推进步骤的边界。
- 允许多个实例同时处于“进行中”，可随时切换，各自独立保留进度；切回某个进行中的实例时，自动定位到该实例自己的当前步骤，切换本身不改变任何实例的执行状态。
- 首版参数统一按文本填写，参数定义保留名称、说明和默认值；支持选中内容转变量、集中填参和命令替换。变量可用于步骤标题、说明和命令，引用同一个参数时共用同一份实例参数值，只需填写一次；执行中修改仍遵循显式应用、仅影响当前及后续步骤和保留已提交快照的规则。内容使用普通字符串与 `{parameterId}` 组成的 TextParts；文字中的花括号保持原样，不自动解析为变量。
- 选中内容转变量时只替换当前选中的这一处，不自动替换其他相同文字；其他位置可再次选中内容并复用已有变量，引用同一参数定义与实例取值。
- 初期执行方式已确认：按步骤顺序从前到后单向推进，不引入依赖图、条件分支等顺序依赖管理。执行中的实例界面优先聚焦当前尚未完成的步骤。失败后停留当前步骤，继续处理并标记完成，或明确跳过后才进入下一步。标记失败必须填写简短失败原因，随本次结果保存；详细评论和截图选填。所有步骤均允许明确跳过，但必须填写原因，不增加“必做/可选”配置。
- 步骤先失败后成功时保留先前结果：每次提交结果自动保存一条记录，默认展示最新结果，旧记录折叠查看，不要求用户手动管理执行轮次。执行过程中可随时在步骤下追加评论与图片附件；评论、附件和结果按时间记录在步骤下，无需指定某次重试。已完成或跳过并推进的步骤允许回看和追加评论、图片，但不得改变已经推进的结果，当前执行位置不回退。
- 首版附件仅支持图片，可直接粘贴或选择本地图片，并在步骤下预览；不支持日志、文档等其他附件类型。已添加的评论允许编辑和删除，误贴图片允许删除，已锁定的步骤结果不受影响。原生将图片存入本实例专属目录，访问需匹配本实例登记的图片条目；仅接受签名一致且不超过 8 MiB 的 PNG、JPEG、WebP、GIF。
- 实例导出需将步骤、参数、结果、评论和图片一起打包为一个文件，导入后完整还原，不依赖原电脑的图片路径或来源模板。存档采用 `.runbook.zip`，包内使用 `runbook.json` 保存结构化数据、`images/` 保存图片，并以包内相对路径关联；JSON 包含格式版本。纯内容模板可单独导出 `.runbook.json`。首版聚焦完整导出与导入还原，不依赖本应用的独立阅读报告后续再加。
- 导入实例与本地已有实例重复时，提示重复，并允许用户选择导入为独立副本；不覆盖本地原实例及其记录。副本独立保存导入内容、参数、结果、评论和图片，不与原实例共享可变数据。
- 执行结束与归档分开：最后一步完成或跳过后自动结束并展示结果汇总，实例仍保留在当前列表；仅在用户手动归档后纳入归档列表并从当前列表移出。归档后仍允许追加评论与截图，已推进的执行结果继续锁定；归档只用于列表整理，不增加补充材料的解锁操作。
- 执行到一半决定不再继续时，允许终止执行并填写一次终止原因；剩余步骤保留为“未执行”，不自动改成逐步跳过。终止后的实例仍在当前列表，等待用户手动归档。首版终止后不恢复，仍可补充评论和图片；需要重新操作时另建实例，也可在当前实例页面直接“复制为新实例”，基于独立副本记录，原实例保持终止状态。
- “复制为新实例”复制当前流程、参数定义和本次参数值，新实例从第一步重新开始，不继承旧结果、评论和图片；这些记录与材料继续保留在原实例，副本与原实例的可变数据独立。
- 模板用于复用，实例独立保存本次内容、参数和执行记录。每条人工提交结果保存当时已替换的标题、说明、命令和参数值快照，不沿用旧版轮次、内容版本和状态更正机制。
- 实例执行中的编辑边界已确认：当前步骤可修改标题、说明和命令；后续步骤可修改、增删和重排，增删重排仅作用于后续部分。已推进步骤的正文、命令和结果冻结，评论与图片按补充材料规则管理。所有流程调整只影响本实例，不回写来源模板。
- 实例中调整后的流程需要复用时，首版只支持另存为新模板，复制流程和参数定义，不带本次执行结果、评论和图片，不提供从实例直接更新来源模板的操作。另存时保留实例携带的参数定义及原默认值，不将本次填写值改成新默认值；需要时再在新模板中修改默认值。
- 创建实例时集中填写流程用到的参数，默认值自动带入；补齐参数后才开始执行，不采用执行到某步时再补缺失参数的初始流程。
- 实例执行中可修改参数，经“应用”确认后只影响当前及后续步骤。已提交的每条结果记录保留当时的命令和参数值，包括当前步骤先前提交的失败记录；已推进步骤的内容和结果不因参数更新而变化。
- JSON Schema 用于表达必要的结构校验规则，不要求用户编辑 Schema。结构合法不代表指令或参数在业务上正确，仍由原生业务规则与用户确认裁决。
- 暂不引入 YAML；不设计 Markdown 解析、标记、源码往返或导入导出兼容层，也不承担旧数据库、旧备份及旧执行记录的迁移要求。

## AI 扩展边界

编辑、手动填参、执行记录和留档不依赖 AI。本轮未实现模型配置、网络请求和 AI 建议入口。后续允许用户自行配置模型服务地址、模型名称和服务需要的认证信息，应能接入远程服务与本机模型服务，具体支持协议待适配设计确定。

首批候选能力为生成步骤/模板草稿，以及建议实例参数；允许只处理单步或少量参数，降低本地小模型的任务复杂度。结果先校验和展示，由用户确认后采纳；实例中的参数和指令变更仍需明确确认，具体交互从简设计。模型不直接修改已产生的执行记录、不自动执行指令。接入不以模型原生支持 JSON Schema 输出为前提。

## 当前实现与验证边界

当前桌面使用 `apps/desktop/src/checklist/` 的 React 清单界面、串行 IPC 队列与缓冲刷新；`native/runbook-checklist` 统一负责 DTO、结构与业务校验、SQLite 用例、图片和 JSON/ZIP 存档。Tauri 只提供窗口、剪贴板、文件选择及保存等桌面能力，不注册维护指令执行入口。

新 `checklist.sqlite3` 用单事务保存结构化 Workspace，图片独立保存于 `checklist-images/<instanceId>/images/`。数据库与已落库状态是持久化权威；动作失败不发布未保存状态，图片删除在数据库提交后清理。旧 `runbook.sqlite3` 不读取、不迁移、不删除。保持现有显式数据路径优先级和错误反馈，不在遇错时静默换库。

导入先校验再预览，确认后提交；文件上限 32 MiB，ZIP 解包总量上限 64 MiB，检查路径穿越、重复条目、缺失或多余图片、图片签名、版本、参数引用和线性结果记录。实例身份按 Windows 路径大小写规则防重，重复实例仅能明确导入为独立副本。导出写临时文件再原子替换，不能交付缺图存档。

首轮使用[五步补丁维护示例](../examples/patch-maintenance/README.md)贯通模板、填参、命令复制、人工结果与评论图片、归档、完整 ZIP 导出和独立副本导入。2026 年 10 月 20 日，原生流程/存档与启动路径的定向测试、桌面 Rust 静态检查及真实 WebView2 闭环验收通过。系统剪贴板中的替换后命令、原生存档生成/校验/导入提交和图片字节均实测；两次正常退出重启后完整 Workspace 保持一致，进行中的实例恢复到第二步并默认展开当前步骤。

系统文件选择框本身未自动操作，测试夹具仅替换其返回内容和保存目的地，并单独注入一次保存失败以验证输入保留及重试；存档业务与持久化仍由真实原生实现处理。维护指令没有执行，剪贴板测试后恢复原内容，重启测试不操作剪贴板。具体验证证据与限制见[验证记录](../testing.md)和当前规划；本轮闭环通过不代表完成真实补丁效率试用、安装分发或全部人工系统对话框验收。

后续再定义 AI 生成与填参契约、服务适配及确认交互；独立阅读报告、安装签名与真实维护效率试用不在本轮闭环范围。保留旧文档和旧验证记录不意味着需要兼容旧设计，也不表示授权删除用户现有文件或数据库。
