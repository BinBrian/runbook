# Markdown 与稳定身份

状态：设计基线。日期：2026 年 10 月 13 日。

## 背景与决定

操作者已有 Markdown 维护文档，需要保留编辑和交换能力。步骤在重排与修改之后必须仍能关联正确记录，代码块又不能被自动判定为需要执行的指令。

采用标准 Markdown 加显式 UUID 的 HTML 注释标记。步骤范围成对标记，指令标记绑定围栏，结果完全存放在独立记录中。文档是内容权威，步骤表与前端卡片都是解析结果。语义由原生核心统一定义。

草稿与有效文档分开保存。无效标记不阻止草稿落盘；实例源码修改在调整模式集中应用。所有正文变化增加步骤内容版本，V0.1 不推断“只是说明修改”的业务影响。

## 备选方案与代价

| 方案 | 取舍 |
| --- | --- |
| 以标题、行号或文本哈希识别步骤 | 编辑方便，但无法可靠区分重复内容或跟随重排，未采用 |
| JSON 结构为权威，Markdown 只是导出 | 更容易直接构建卡片，但损失现有原文编辑与交换能力，未采用 |
| 正文加侧边元数据文件 | 原文干净，但复制和导入时容易失去身份对应，未采用 |
| 正文内显式标记 | 一份文件携带内容与身份，普通阅读器隐藏注释，采用 |

代价是源码出现标记，用户直接编辑时可能临时破坏语法。常用转换由界面完成，错误草稿仍自动保存。UUID 重复显式报错，不用相似内容自动修复关联。

V0.1 只支持顶层步骤与可确定源码范围的指令围栏；嵌套转换需要用户调整选区。未来是否扩展语法，应由真实维护文档的转换阻力决定。

## 验证条件

验证重排保留身份、复制生成新身份、标记假文本不被解释、错误草稿恢复以及指令字节范围。指令复制必须保留正文空白，并明确定义围栏结构换行。

唯一语法定义见[Markdown 文档模型](../subsystems/document.md)。JSON 用于完整记录恢复，Markdown 用于内容交换，二者不承诺相同恢复能力。
