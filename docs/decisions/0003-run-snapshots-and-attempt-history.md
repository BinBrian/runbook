# 独立实例与记录历史

状态：设计基线。日期：2026 年 10 月 13 日。

## 背景与决定

一次维护常有临时调整、失败与重试。若实例直接引用模板当前内容，模板修改会改变旧记录；若重试覆盖结果，后续无法理解异常是如何处理的。

实例创建时冻结完整来源快照，并持有独立 Markdown 工作副本。步骤使用稳定身份和递增内容版本。每次实际再次记录新增 attempt，冻结当时的说明与指令；终态只读，说明与误标更正追加保存。

当前结论由当前内容版本的最新轮次和更正计算。源码正文变化使当前状态待处理，重排保留结果。移除步骤只退出当前流程，历史对象仍存在。结束留档冻结整份实例；后续继续维护建立新实例。

## 备选方案与代价

| 方案 | 取舍 |
| --- | --- |
| 实例共享模板当前内容 | 存储少，但旧记录会随模板变化，未采用 |
| 每步只存最后状态和回显 | 查询简单，但失败与重试信息丢失，未采用 |
| 所有输入都保存为事件流 | 还原能力强，但增加本版不需要的回放与投影维护，未采用 |
| 文档快照加步骤轮次及追加更正 | 满足隔离与留档，实体数量有限，采用 |

代价是重复保存部分文档与步骤内容，报告要区分当前结论和历史结果。V0.1 接受此存储代价，不建设完整模板版本控制或逐字编辑事件流。

## 验证条件

验证两个实例互不影响、模板归档后实例独立打开、失败重试保留回显、正文修改使旧成功失效、误标更正不增加轮次、移除步骤历史可见以及完整 JSON 独立恢复。

状态规则见[执行记录模型](../subsystems/execution.md)，存储与恢复规则见[本地存储模型](../subsystems/storage.md)。
