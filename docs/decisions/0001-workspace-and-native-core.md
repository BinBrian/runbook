# 工程组织与原生核心

状态：设计基线。日期：2026 年 10 月 13 日。

实施补充：仓储与用例已拆为 native/runbook-store，Tauri 保留薄适配层，固定 perform 命令接收类型化 Action。调整与限制见 [ADR 0004](0004-store-and-nested-backup.md)，以下保留原始决定背景。

## 背景与决定

用户指定新项目放在 `runbook/`，设计、架构和决策都保存在该项目，并要求工程结构参考 `deepseek-harness/`。产品技术栈已经确定为 Tauri 2 与 React，持久化为 SQLite。

采用 `apps/desktop` 组合应用，`packages/<group>/<package>` 放前端功能包，`native/runbook-core` 放纯 Rust 语义核心，`docs` 分离产品、交互、架构、子系统与决策。包数量只覆盖当前 MVP，参考项目不成为运行时依赖。

Rust 核心统一解释 Runbook 文档和执行状态；桌面原生服务执行用例并持有 SQLite 事务，前端只调用命名接口。Rust DTO 单向生成 TypeScript 类型，编辑器位置转换由单独功能包负责。

## 备选方案与代价

| 方案 | 取舍 |
| --- | --- |
| 单个 React 应用加 src-tauri | 初期配置更少，但编辑器、接口和业务职责容易混在入口内，未采用 |
| 复制 Harness 的完整插件、Host 和 Web 结构 | 扩展面大，但增加本版无需求的运行时和服务，未采用 |
| 前端 SQL 插件与前端状态机 | 写入路径更短，但文档应用、历史保护与导入事务分散，未采用 |
| 应用组合加少量功能包与原生核心 | 满足参考结构要求，并集中持久化规则，采用 |

代价是维护 TypeScript 与 Rust 工具链，以及跨进程 DTO 和 Unicode 位置换算。通过生成类型、契约用例和集中适配减少漂移。此选择不要求 V0.1 实现插件扩展或多个产品入口。

## 验证条件

M0 验证 workspace 依赖、Tauri 路径、生成类型与 Serde 编码一致；后续验证单事务写入与错误回滚。最终包名、脚本和依赖版本以实现时的清单为准，不能把当前目录图当作已存在源码。

结构定义见[整体架构](../architecture.md)。只有新增独立应用或存在实际复用需求时，才进一步拆分服务或功能包。
