# 示例补丁维护：使用与验收

状态：2026 年 10 月 20 日已接入清单版桌面程序。新库预置同一五步示例模板，可在“模板”中创建实例；完整闭环及正常重启已通过隔离桌面验证。产品行为以用户确认和 [ADR 0008](../../decisions/0008-json-content-and-optional-ai.md) 为准。

用户已同意先使用示例流程验证设计。以下环境、路径、工具和结果均为虚构；命令作为记录与复制内容，未在本轮执行。`Demo-PatchTool` 是示例工具名称，不是随应用提供的执行能力。

## 五步清单

| 步骤 | 说明 | 命令数 | 示例处理 |
| --- | --- | --- | --- |
| 1. 核对维护目标 | 确认环境、目标版本和维护窗口 | 0 | 人工标记完成 |
| 2. 检查补丁包 | 查看文件信息、核对 SHA256 | 2 | 先标记失败，补充评论和图片，修改包路径后再次标记完成 |
| 3. 确认已有可用备份 | 在外部工具完成备份、确认恢复方式 | 0 | 仅在这次虚构演练中跳过，填写跳过原因 |
| 4. 在外部工具应用补丁 | 复制示例命令，到外部工具自行操作 | 1 | 人工标记完成 |
| 5. 核对维护结果 | 核对版本、服务状态及人工抽查 | 1 | 人工标记完成；稍后手动归档并追加评论 |

步骤 2 的两条命令共用一个步骤结果。步骤 1、3 是同一种步骤结构，只是没有命令。

## 参数填写

| 名称 | 模板默认值 | 本次值 |
| --- | --- | --- |
| 环境 | 演示环境 | 演示环境 A |
| 目标版本 | 0.1.0 | 0.1.1 |
| 补丁包路径 | 空 | `C:\RunbookDemo\packages\patch-0.1.1.zip`，失败后应用新值 `C:\RunbookDemo\packages\patch-0.1.1-repacked.zip` |
| 目标目录 | `C:\RunbookDemo\service` | 沿用默认值 |

创建实例时自动带入默认值，补齐包路径并确认本次值后开始。环境和版本在标题、说明及命令中复用，只填一遍。参数值均为文本。

模板编辑时选中固定内容可创建变量，其他位置再次选中并选择复用已有变量。转换只改变当前选区，界面显示参数标签。上述路径只用于演示文本替换，不能直接作为真实维护方案。

## 执行页示意

步骤 2 首次标记失败、应用新包路径后，页面默认如下：

```text
补丁维护 / 演示环境 A                  进行中 · 1/5 已推进

✓ 1. 核对演示环境 A 的维护目标                         [展开]
▼ 2. 检查补丁包                                       当前步骤
    核对文件是否存在，并比对发布清单中的 SHA256。
    ┌ Get-Item -LiteralPath '...patch-0.1.1-repacked.zip'   [复制] ┐
    └──────────────────────────────────────────────────────────┘
    ┌ Get-FileHash ... -Algorithm SHA256                   [复制] ┐
    └──────────────────────────────────────────────────────────┘
    上次结果：失败，补丁包 SHA256 与发布清单不一致。     [历史]
    评论：已重新取得补丁包，准备更新本次包路径。
    图片：占位图，仅用于验证附件随包传递。
    [完成并下一步] [记录失败] [跳过并填写原因]
    [添加评论] [粘贴或选择图片]
○ 3. 确认已有可用备份                                  [展开]
○ 4. 在外部工具应用补丁                                [展开]
○ 5. 核对演示环境 A 的维护结果                         [展开]
```

这里的命令因版面省略了路径；真实卡片与复制内容必须保留完整文本。当前步骤内容使用本次已应用参数，上次失败结果继续显示当时的包路径，不能把旧失败附会到新命令上。

## 走查结果与验收口径

| 场景 | 本样例如何表达 | 桌面验收口径 |
| --- | --- | --- |
| 开始前填参 | 模板默认值与实例值分开保存 | 引用参数未补齐时，不能开始 |
| 失败后继续 | 步骤 2 保留失败、成功两条结果及各自快照 | 失败停留当前步骤，失败原因必填；完成后再推进 |
| 执行中改参 | 旧结果保存旧路径；新结果保存已应用的新路径 | 点击应用后只改变当前、后续步骤；已推进步骤保持原内容 |
| 实例独立编辑 | 实例持有完整 document，不依赖来源模板取正文 | 当前步骤可改内容；后续可增删重排；已推进步骤不能改正文、命令和结果 |
| 图片和评论 | entries 中按时间归属步骤；允许结束、归档后补充 | 评论可编辑删除，误贴图片可删除；结果快照不变 |
| 完成与归档 | status 为 completed，archivedAt 另存 | 最后一步推进后显示汇总，仍在当前列表；手动归档后才移出 |
| 多实例 | 每个实例独立持有参数、记录及当前步骤 | 切回进行中的实例定位到自己的当前步骤 |
| 完整存档 | ZIP 内含 runbook.json 与被引用图片 | 原电脑、原模板或原图片路径缺失时仍能还原 |

已结束或归档的实例可追加材料，不代表可以改写已提交结果。失败、跳过和终止的原因应随各自结果或终止信息保存，详细评论和图片选填。

## 两种副本的区别

| 操作 | 流程与本次参数值 | 旧结果、评论和图片 | 进度 |
| --- | --- | --- | --- |
| 复制为新实例 | 复制当前实例携带的流程、定义和本次值 | 继续留在原实例，不带到新实例 | 从第一步重新开始 |
| 重复导入存档为独立副本 | 完整恢复存档内容 | 完整恢复到独立副本 | 保留存档时的进度与结束、归档信息 |

终止分支也适用：假设在步骤 2 停止，填写一次终止原因，后续步骤保持未执行；原实例不能恢复，但可继续补充材料。点击“复制为新实例”后，以当前流程和参数值创建一个新的未开始实例，确认参数后从第一步开始。

“另存为新模板”再作区分：复制实例流程和参数定义，保留定义中的原默认值。例如本次使用版本 0.1.1，新模板仍保留原默认值 0.1.0；执行结果、评论、图片及本次填写值不进入新模板。

## 文件与字段

- [template.runbook.json](template.runbook.json)：独立可复用模板。
- [runbook.json](runbook.json)：演示完成、手动归档并补充评论后的完整实例。
- [patch-maintenance.runbook.zip](patch-maintenance.runbook.zip)：同一实例 JSON 与图片组成的存档夹具。
- [verify.py](verify.py)：只读样例自检，使用 Python 标准库，不启动命令或连接业务服务。

`document` 只保存流程内容和参数定义。实例另存 `parameterValues`、进度、结束信息、归档信息和步骤材料。`sourceTemplateId` 只用于来源追溯，打开实例无需再读取该模板。

标题、说明和命令采用文本片段数组：普通文字直接为字符串，变量引用为 `{ "parameterId": "version" }`。界面是多行文本、命令卡片和标签；内部表示能区分命令原有的花括号与用户手动插入的变量。参数 ID 在本份文档内稳定，显示名称可单独维护。

结果的 `snapshot` 保存当时已替换的标题、说明、命令和参数值，供历史展示与复制；不要用当前参数重新渲染历史。`entries` 统一按顺序保存步骤结果、评论与图片，命令不带独立状态。图片只引用包内相对路径。

原生 `runbook-checklist` 已实现结构、参数引用、状态机与 ZIP 路径/图片校验；[模板 JSON Schema](../../schema/template.schema.json) 提供结构参考。此目录的自检仍仅检查固定样例和内存变体，完整桌面实现另有原生测试和实际 WebView2 验证。

## 自检与限制

在工作区执行：

```powershell
python docs/examples/patch-maintenance/verify.py
```

自检检查 JSON 结构与引用、单向结果顺序、失败和跳过原因、旧新参数快照、原默认值保留、两种副本的数据区别，以及 ZIP 中 JSON 和图片字节的完整性。

附件是 16×16 的 PNG 占位图，只用于检查图片随包保存，不是真实终端截图。另行执行的桌面验收已验证选区变量、自动保存失败保护、系统剪贴板回读、图片预览、完整存档和独立副本恢复，以及两次正常重启。系统导入/导出文件对话框的返回文件和保存目标由夹具替换，实际 ZIP、导入校验和提交没有替换；真实维护效率、其他机器和系统文件对话框的人工操作仍待试用。详见[验证记录](../../testing.md)。
