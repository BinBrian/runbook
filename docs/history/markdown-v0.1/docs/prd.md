# Windows Runbook 产品需求

V0.1 面向使用补丁维护 Markdown 的 Windows 操作者。首要目标是让同一份文档在重复维护中更容易复制正确指令、识别未处理步骤、保留异常处理过程，并在事后还原本次记录。

产品提供人工操作辅助。复制、勾选和回显均由用户触发；完成状态是用户的确认，不代表系统验证了外部终端结果。

## 产品范围

| 模块 | V0.1 内容 | 优先级 |
| --- | --- | --- |
| Markdown 编辑 | 粘贴、编辑、导入与预览原始文档 | P0 |
| 指令块 | 手动转换步骤与指令、一键复制单条或多行指令 | P0 |
| 流程执行 | 完成、失败、跳过，新增、移除、修改、复制与重排步骤 | P0 |
| 运行结果 | 粘贴文本回显、记录异常、重试与重复操作 | P0 |
| 模板管理 | 保存和管理模板，创建互不影响的执行实例 | P0 |
| 本地存储 | 自动保存、恢复进行中实例、执行历史、Markdown 与 JSON 导入导出 | P0 |
| 模板参数化 | 选中文本转变量、默认值、实例填写及独立修改 | 当前迭代 |
| 桌面增强 | 窗口置顶、精简模式、快捷键 | P1 |
| 随想便签 | 自由记录、移动端、跨设备同步 | 暂缓 |

V0.1 不建设账号、云服务、远程服务器、终端模拟器、自动命令执行、流程依赖图或条件分支引擎。历史记录范围是执行实例及其操作轮次；完整 Markdown 编辑撤销历史和模板版本浏览不属于本版承诺。

参数化纳入本轮迭代。模板定义变量与默认值，实例创建时填写自己的参数，执行区显示和复制替换后的内容。普通占位符不隐式求值，仅处理显式声明的 Runbook 变量；不执行脚本或命令。其余 P1 不阻塞当前验收。

## 使用流程

1. 粘贴或导入现有 Markdown，预览全文，手动选择需要跟踪的内容。
2. 将选区转换为步骤，按需将其中的代码块或文本转换为指令。说明、检查事项和普通代码块仍可作为阅读内容。
3. 将重复使用时会变化的文本选中转为变量，设置名称和默认值。点击“创建执行实例”，输入本次名称、背景及参数。
4. 在实例中复制指令，到外部工具执行，粘贴回显并标记完成、失败或跳过。
5. 失败后保留原记录，调整本实例的流程或再次记录同一步骤，完成后结束并留档。
6. 下次从模板创建新实例；未结束的实例可从历史恢复继续记录。

同一步骤可以包含多条指令，也可以只是人工检查事项。V0.1 记录步骤级结果，不设置独立的指令完成状态。使用者需要分别确认每条指令时，可以将它们拆成多个步骤。

## 业务规则

| 场景 | 规则 |
| --- | --- |
| 导入普通 Markdown | 完整保留正文；标题、任务列表或代码围栏不会自动成为执行步骤 |
| 手动转换 | 操作者明确指定步骤和可复制指令；转换可以在编辑器当前会话撤销 |
| 复制指令 | 只显示“已复制”；不创建轮次，不改变结果，不自动跳到下一步 |
| 创建实例 | 保存当时模板的完整快照和独立文档；之后模板修改或归档不影响实例 |
| 参数默认值 | 选区文本作为初始默认值，可修改；同名变量的多个引用共享该对象的参数值 |
| 实例参数 | 创建时填写，后续独立编辑；文档与参数一起自动保存草稿，经显式应用更新流程 |
| 参数影响记录 | 替换后的步骤正文改变才增加内容版本并恢复待处理；旧轮次保存当时指令和参数 |
| 独立编辑能力 | 模板与实例共用编辑器，都可改正文、指令、顺序、检查点和变量；实例不向模板写回 |
| 标记结果 | 用户主动确认；失败和跳过需要说明，回显允许为空 |
| 重试或再次操作 | 新建一轮记录，旧轮次的说明、指令、结果和回显仍可查看 |
| 修改已记录步骤 | 步骤正文变化产生新内容版本，当前状态恢复待处理；旧记录保留 |
| 修改说明或标题 | V0.1 按正文变化处理，提示需要重新确认，避免猜测修改是否影响操作 |
| 重排步骤 | 身份、内容版本和记录跟随原步骤，结果不因位置变化失效 |
| 复制步骤 | 产生新的步骤和指令 ID，状态为待处理 |
| 移除步骤 | 当前流程不再计入该步骤，历史保留其所有轮次 |
| 修改原始标记出错 | 自动保存草稿，显示错误位置；不应用到执行流程 |
| 更正误标结果 | 追加带原因的更正记录；与实际重试区分，不虚增操作轮次 |
| 结束实例 | 显示完成、失败、跳过、待处理和记录中数量；先处理记录中轮次，再留档失败或未完成的记录 |
| 再次执行整个流程 | 创建新实例并清空操作状态；已留档实例保持只读 |

使用者可以跳到任意步骤，步骤顺序仅用于导航。工具不推断前置条件，也不阻止使用者在外部终端进行操作。

步骤记录的是开始本轮记录时的说明与指令版本。工具无法观测外部终端的实际输入；界面与报告不能把该快照称为自动采集的实际执行命令。

## 自动保存与留档

编辑内容与回显自动保存，界面显示“保存中”“已保存”或“保存失败”。只有本地事务成功才显示“已保存”。正常退出等待待保存内容落盘；保存失败时保留输入并提供重试和临时导出。

执行实例的源码调整集中在“调整流程”模式。草稿持续自动保存，点击“应用并返回执行”后才更新流程。无效草稿不会替换已应用的指令；执行区域明确显示所用版本。已有记录中的步骤正文在调整后恢复待处理，单纯移动不触发此规则。

结束留档是显式操作。历史分别展示全部完成、含跳过、含失败、未完成或没有步骤，不能把“所有步骤都已处理”等同于成功。若仍有正在记录的轮次，结束对话框要求先标记结果或作废本轮记录。

进行中实例的汇总单独显示记录中数量，各状态计数之和等于当前步骤总数。

留档前先应用或明确放弃未应用的源码草稿，使历史页面和报告对应同一份最终流程。

## 数据交换

| 格式 | 用途 | 恢复能力 |
| --- | --- | --- |
| 普通 Markdown | 导入原文或导出当前内容并移除交互标记 | 恢复正文；需手动转换 |
| Runbook Markdown | 模板与流程交换 | 标记保留时恢复步骤和指令定义，不带执行状态 |
| 执行报告 Markdown | 阅读和留档 | 包含轮次、回显、异常及结论，不作为历史恢复格式 |
| Runbook JSON | 完整备份和恢复 | 恢复文档、实例快照、已移除步骤、轮次、回显和更正 |

JSON 导入先校验整包，默认创建独立副本，失败时不留下部分数据。不覆盖现有模板和实例，不自动从较新格式降级。

普通 Markdown 导出保留当前正文和代码围栏，移除 Runbook 格式、步骤与指令标记，不包含执行结果。来源模板缺失或已归档时，实例仍可独立打开和复制流程；从原模板重新开始需要可用的本地模板。

参数化内容导出普通 Markdown 时使用模板默认值或实例自己的已应用值。Runbook Markdown 保留可复用变量定义，导出实例时在导出副本中将本次参数写成默认值；不会回写实例或原模板。完整 JSON 保存草稿参数、已应用参数和历史参数快照。

## MVP 实施阶段

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| M0 工程与契约 | pnpm workspace、Tauri 壳、原生核心、类型生成与测试入口 | Windows 开发窗口可打开，IPC 示例与生成类型一致 |
| M1 内容与模板 | CodeMirror 编辑预览、标记转换、复制、模板自动保存 | 示例流程转换与复制准确，错误标记草稿可恢复 |
| M2 执行记录 | 实例快照、步骤结果、回显、重试、更正与流程调整 | 隔离、重排、修改失效与历史保留用例通过 |
| M3 存储闭环 | 启动恢复、留档、历史、Markdown 与 JSON 导入导出 | 保存与恢复一致，完整 JSON 往返通过 |
| M4 真实试用 | 原始 Markdown 与工具的对照试用 | 正确性门槛通过，记录效率与出错情况 |

各阶段是同一 MVP 的实施顺序，M1 或 M2 完成不能代表 V0.1 已交付。依赖版本、Windows 运行前置条件和开发命令在 M0 固定并记录，不照搬参考项目的依赖版本。

## 正确性验收

| 编号 | 场景 | 验收要求 |
| --- | --- | --- |
| A01 | 中文、引号、反引号、反斜杠、多行与空白的复制 | 与文档模型定义的指令正文完全一致，无围栏、说明或额外结构换行 |
| A02 | 同一模板创建两个实例，再改模板和其中一个实例 | 三份内容互不污染，实例能查看创建时快照 |
| A03 | 复制未处理步骤的指令 | 步骤保持未处理，轮次数不增加 |
| A04 | 失败后重试并完成 | 新旧轮次、指令快照、回显和异常都保留，当前结果取新轮次 |
| A05 | 重排、重命名、改指令与移除已记录步骤 | 重排不串记录；正文修改恢复待处理；移除步骤历史仍可见 |
| A06 | 输入暂时不闭合的标记、重复 ID、错误围栏后关闭 | 已保存草稿可恢复，已应用流程未被错误替换 |
| A07 | 保存中退出、保存失败与异常退出 | 正常退出完成落盘；异常退出恢复最后已确认保存版本，未确认内容不作恢复保证 |
| A08 | 更正误点结果 | 原结果及更正原因、时间保留，轮次数不增加 |
| A09 | JSON 导出后在空数据库导入 | 快照、当前流程、移除步骤、轮次、回显、更正与留档结论一致 |
| A10 | JSON 重复导入、未知版本或悬空关联 | 合法包创建独立副本；非法包整包拒绝，不覆盖原对象 |
| A11 | 含失败、跳过和待处理项时留档 | 计数与结论准确，不能显示全部完成 |
| A12 | 断开网络，执行完整内容与记录流程 | 核心编辑、复制、记录、恢复及导出均可使用 |
| A13 | 已完成步骤再次记录，模板归档与恢复 | 新轮次不覆盖成功记录；归档来源不影响实例，恢复模板后可创建新实例 |
| A14 | 文本转变量、默认值与两个不同参数实例 | 单次精确替换，同模板的多个实例各自持有填写值；模板更新不改已有实例 |
| A15 | 实例改参数后保存、重启并应用 | 草稿能恢复；应用前执行仍使用旧值；应用后受影响步骤待处理，旧轮次参数与回显不变 |
| A16 | 变量值含引号、换行、反引号或类似标记的文本 | 字符保留，不递归替换；破坏步骤或指令边界时明确拒绝，不产生新执行结构 |
| A17 | schema 1 数据升级与旧 JSON 导入 | 升级前一致性备份，保留旧文档和记录，缺少参数按空集合解释；schema 2 往返保持参数与快照 |

## 核心目标试用

选择一份真实补丁维护文档，建议包含 8 至 12 个步骤和 6 至 15 条指令。比较两种方式完成同等操作与记录的用时，分别包含正常流程和“失败、调整、重试、关闭恢复”流程。首次模板整理成本单独计时；对照试用采用交叉顺序，减少熟悉度影响。

正确性发布门槛为指令复制准确、实例隔离和历史保留均达到 100%，试用中漏步骤、错复制和回显被覆盖均为 0。以下效率数值是待验证的产品目标，不是已取得的结果：首次整理不超过 10 分钟；创建实例到复制首条指令不超过 30 秒；每条指令一次点击复制；排除外部操作等待时间和首次整理成本后，操作与记录时间比直接使用 Markdown 减少至少 25%。

目前只有[结构示例](../../../../examples/patch-maintenance.raw.md)，尚无用户指定的真实补丁文档与实测数据。效率未改善时，优先调整复制、记录和导航交互，不以新增 P1 功能替代验收。
