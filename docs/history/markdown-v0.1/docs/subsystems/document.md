# Runbook Markdown 文档模型

Markdown 是模板和实例流程的内容权威。Runbook 用标准 HTML 注释增加稳定身份与指令语义，不在文档中保存完成状态、回显或操作轮次。

## 参数定义与替换

本轮新增单个顶层 `<!-- runbook:parameters {"HOST":"staging"} -->` 定义，正文通过 `{{rb:HOST}}` 引用。名称使用 1–64 位 ASCII 标识符，默认值为字符串。JSON 写出须将可能结束注释的字符编码；围栏内的类似定义不解释为元数据。具体所有权与兼容选择见 [ADR 0006](../../../../decisions/0006-parameters-and-independent-instances.md)。

模板和实例均保留带占位符的源码。模板预览可以使用默认值；实例执行使用自己已应用的参数值。变量替换为一次字面替换，不递归展开值内占位符，不进行 shell 转义。空白、引号、Unicode 和换行保留；步骤/指令身份和边界必须与原始文档一致，无法保证时拒绝应用。未声明的 Runbook 引用不能作为有效流程应用。

实例的步骤投影来自替换后的 Markdown，编辑变换仍针对原始 Markdown 的解析范围。两种范围不能混用；应用差异比较使用替换后的内容。历史记录保存当轮替换后的步骤与参数，不以当前值重新渲染旧记录。

## 标记语法

交互文档含一个顶层格式标记 `<!-- runbook:document version="1" -->`。步骤以 `<!-- runbook:step id="UUID" -->` 开始，以 `<!-- /runbook:step -->` 结束。步骤内部的 `<!-- runbook:command id="UUID" -->` 绑定紧邻的代码围栏，中间只允许空行。

具体示例见[标记后的维护流程](../../../../../examples/patch-maintenance.runbook.md)。普通 Markdown 无需格式标记；第一次转换时添加标记。未知的 Runbook 格式版本作为草稿保存并报告不兼容，不按当前版本猜测。

| 约束 | 定义 |
| --- | --- |
| 步骤身份 | `(document_id, step_id)`，UUID 不随标题、行号或顺序改变 |
| 指令身份 | `(document_id, command_id)`，UUID 在整份文档内唯一 |
| 合法位置 | 步骤标记与指令围栏处于顶层 Markdown 块；步骤不能嵌套 |
| 假标记 | 围栏、引用或普通行内内容中的同样文本不解释为标记 |
| 步骤正文 | 成对标记之间的 Markdown，允许说明、普通代码和多个指令 |
| 标题 | 首个标题的文本，否则取首个非空正文行；没有可读正文时提示补充 |
| 人工检查 | 步骤可以没有指令块，仍可记录完成、失败或跳过 |
| 普通代码 | 没有 command 标记的代码围栏只作为阅读内容 |

未闭合、嵌套、重复 ID、没有围栏的 command 或越界 command 都是可定位的错误。正文自动保存，但不能将该草稿作为有效流程应用。不会以标题相似度或内容哈希合并步骤。

## 选择与源码变换

编辑操作尽量保留原始 Markdown，仅添加或移除必要标记。“转为步骤”仍要求完整顶层块；普通顶层段落中的“转为指令”按实际选区转换，支持相邻行没有空行时单独选择其中一行，也支持局部正文。前后未选文字保留在指令外，必要空行只作为 Markdown 分隔加入。嵌套列表、引用或其他结构的局部选区仍需调整范围，工具不猜测或改写其层级。

已有代码围栏转换为指令时保留语言和正文，增加稳定指令标记。普通文本转换时选择不会与正文冲突的围栏字符和长度，保持文本顺序与内容，不将多个独立指令隐式合并。

移动步骤搬移整个标记区段。复制步骤为步骤与所有指令生成新 UUID。用户手工复制源码产生重复 ID 时展示错误，由明确的“修复重复身份”操作生成新 ID，不静默重挂历史。

取消指令标记保留围栏；取消步骤标记保留正文并移除其内部交互标记。真正移除步骤删除整个区段，在实例中仍保留历史对象。

普通 Markdown 导出只移除合法的 Runbook 格式、步骤与指令标记，保留当前正文、围栏和语言标签；围栏内的假标记不删除。Runbook Markdown 导出保留标记。两种导出都不含执行结果，且不承诺撤销到首次导入的内容。

## 指令正文与复制

指令通过源码范围切片获得，不使用 `.trim()`，不依赖 Markdown 解析器可能归一化后的代码文本。复制不含围栏、语言标签、Runbook 标记、步骤说明或其他指令。

正文范围从开围栏行结束之后开始，到闭围栏前的一个结构行结束符之前结束。该结构行结束符是围栏语法分隔，不属于复制正文；正文内部的 CRLF 或 LF、中文、空格、空行与字符全部保留。未闭合围栏或无法确定范围时禁用指令复制并报告错误。

范围计算须覆盖空围栏，不能生成反向范围。没有非空白字符的正文不允许转换成指令；已经标记的空指令作为草稿诊断处理，普通空代码围栏仍可保留为阅读内容。

普通文本转换时始终在选中文本之后另加一个结构行结束符，再写闭围栏。这样选区本来没有末尾换行时，复制不会凭空增加换行；选区本来含末尾换行时，该换行仍属于正文。为已有围栏加标记时，以本节定义的正文范围为复制内容，不猜测原作者是否想在粘贴时提交命令。

测试必须覆盖无末尾换行、原本含末尾换行、多个空行、CRLF、LF、长围栏、波浪线围栏和正文中出现反引号的情况。复制按钮在成功写入剪贴板后才显示“已复制”。

## 步骤版本

行号与源码范围仅用于当前 revision 的定位。步骤身份不使用范围或哈希。

步骤内容摘要对标记内部正文计算，仅统一比较时的 CRLF 与 LF，不删除空白或做 Unicode 归一化。内容变化增加 `content_version`；移动步骤、仅移动标记外的说明不增加。V0.1 对标题与说明修改也按正文变化处理。

哈希相同仅用于判断正文是否变化；步骤曾变化后再改回原文，内容版本仍递增，不能自动恢复早先的成功状态。已移除步骤重新进入流程也增加内容版本。

## 解析权威

Rust 核心定义标记、源码范围、指令正文与步骤差异。前端可以即时预览和提示，但持久化、实例创建与 JSON 导入必须通过同一原生入口。当前标记版本为 1；解析结果提供 source_hash，模板持久化此摘要，步骤保存 content_hash。V0.1 未持久化独立 parser_version，也未为实例另存 source_hash；未来修改解析语义前须先定义版本及兼容策略。

暂时无效的源码仍保存在草稿中。模板有效草稿可自动应用；实例调整在用户点击应用后更新有效文档和步骤投影。当前 Document 不携带 revision；界面核对解析请求原文仍等于当前原文，步骤变换前重新解析。持久化写入以对象 revision 校验，旧范围不能直接套用新原文。
