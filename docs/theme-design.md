# Runbook 主题与视觉规范

## 当前视觉规则（2026 年 10 月 23 日）

本节按本轮用户确认更新，优先于后文保留的历史规则和旧色值表，尤其取代“全局橙、局部蓝”的范围配色。实施与实际验收状态以现有规划及[验证记录](testing.md)为准。纯白/暗夜、蓝色主操作、单个太阳/月亮入口和本机显示偏好继续沿用。

| 对象或状态 | 两主题共同语义 |
| --- | --- |
| 普通全局、组局部、步骤局部变量 | 使用正文中性色；依靠树层级、全局/组/步骤标题和菜单归属表达范围 |
| 当前选中变量、焦点和主操作 | 蓝色文字、轻选中底或焦点环；不改变执行结果颜色 |
| 缺值与未应用修改 | 橙色文字/小标记；缺值正文标签及摘要使用注意色浅底、边框和虚线，辅以明确状态文字 |
| 同时选中且缺值/未应用 | 保留蓝色选中底与焦点，变量文字和状态标记仍表达橙色注意状态 |
| 完成、失败、跳过 | 沿用各自结果色和状态文字；不得被变量范围或当前阅读高亮覆盖 |

变量常态令牌 `--variable-global` 与 `--variable-local` 均指向 `--text`。变量注意状态独立使用下表，不能再把橙色解释为全局范围。

| 变量注意令牌 | 纯白 | 暗夜 |
| --- | --- | --- |
| `--variable-attention` | `#a94b08` | `#f2b56b` |
| `--variable-attention-soft` | `#fff4e8` | `#382b20` |
| `--variable-attention-border` | `#e7bd91` | `#84603b` |

标题箭头、编辑入口及标题文本具有独立命中区域，标题单击不再承担折叠。编辑入口在悬停或键盘聚焦时可见，新增步骤直接聚焦标题；布局变化不能移动点击目标。图片预览关闭按钮的图标与底色须有可辨对比度，两主题的悬停和键盘焦点也须可见。

变量菜单用一次名称与范围标题解释当前对象，再列简短动作。未应用命令提示只出现在引用相关变量的卡片上，同时区分生效值与待应用值；正文命令保持生效值，提示不能把整段命令染色。正文过滤反馈固定在内容上方，提供对象、步骤数、引用次数和“显示全部”，恢复后回到原阅读锚点。正文变量自动定位保留过滤与阅读位置。

窄窗（不超过 1000px，含 940px 验收规格）保留独立 44px 变量轨道，入口显示待填/未应用计数；打开为右侧 360px 临时面板，不通过压缩字号或正文宽度容纳。背景遮罩与面板避开应用顶栏，关闭可回正文；宽窄开闭偏好分别保存，仅主动操作写入。宽窗继续正常并列。底部当前步骤操作条独占一行，位于可滚动正文之后，不能盖住末行命令或补充记录。

开始区按准备开始、缺值、参数就绪、修改待应用分别表达；有草稿的动作显示“应用并开始”。缺值/未应用用橙色注意状态，准备好或普通开始入口不能冒充已完成绿色结果。所有视觉状态保持变量草稿显式应用、历史冻结与业务数据不变。

## 历史主题方案与验收背景

以下保留 2026 年 10 月 21 日方案及原始色值说明。与本节冲突的范围颜色和布局描述由当前规则取代，其他基础主题职责继续有效。

状态：2026 年 10 月 21 日已按用户提供的布局参考实现纯白/中性暗夜与蓝色强调。顶部通过单个太阳/月亮图标按钮切换，默认纯白；显示偏好保存在本机，不进入业务存档。验证证据与边界见 [验证记录](testing.md)。

## 设计目标

采用纯白和中性暗夜两套底色。中性色承载内容与层次，少量强调色引导当前操作，语义状态色表达结果、警告和危险反馈。浅色与暗夜共用操作逻辑、信息层级和控件位置。

参考 [Fluent 2 Color](https://fluent2.microsoft.design/color)：中性色用于表面、文字和布局；品牌色用于有限的突出位置，避免大面积铺色；语义色传达重要反馈，并与文字或图形共同使用。本规范是 Runbook 的产品约束，不要求引入 Fluent 组件库。

## 颜色职责

| 类型 | 允许使用的位置 | 约束 |
| --- | --- | --- |
| 中性色 | 窗口、侧栏、工具栏、卡片、菜单、输入区、标题、正文、命令、参数值、分隔线及常规图标 | 建立界面主体；灰色不混入持续可感知的绿色倾向 |
| 强调色 | 当前主导航的小标记或淡选中底、当前执行步骤的小标记、主要按钮、选中控件与焦点环 | 同一操作区域仅有一个最突出动作；不铺满侧栏、整张步骤卡或步骤组 |
| 变量范围色 | 开始记录/补齐参数摘要中的待填变量标签，橙色为全局、蓝色为局部 | 仅为用户确认的摘要辨认规则；局部同时显示命名空间，使用独立令牌，不表示执行结果或把正文变量全部染色 |
| 成功色 | 已完成标记、成功结果及短暂成功反馈 | 不因按钮会记录“完成”就把按钮归为成功状态 |
| 注意色 | 跳过、缺失必填参数、未应用修改等需要处理或关注的提示 | 使用局部标签、图标或细边线，并保留具体文字；普通待处理不默认染黄 |
| 失败色 | 已记录失败、保存错误、字段校验错误 | “记录失败”入口是中性按钮；提交后的失败结果才使用失败色 |
| 危险色 | 删除、终止等不可逆操作的最终确认及明确危险提示 | 这是危险操作的语义例外；不将普通“记录失败”动作设计成危险确认按钮 |

强调色与成功色分别定义，不共用一个 `green` 角色；即便未来选择相近色相，也不能共用可变令牌。更换强调色不得改变已完成、失败或跳过的含义。

## 组件落点

| 区域 | 视觉规则 |
| --- | --- |
| 应用侧栏与顶栏 | 统一为中性表面。主导航仅选中行保留短色条或很淡的强调背景，文字和普通图标保持中性 |
| 步骤标题与说明 | 标题使用正常正文主色，通过字号、字重和间距建立层级。当前步骤仅保留小标记，空标题/描述使用可辨认的灰色占位 |
| 步骤组 | 通过组标题、留白和少量分隔表达层级，减少组框套子步骤框的视觉重量；保留现有折叠、组内/组后动作位置 |
| 命令卡 | 保留无标题文字的浅灰操作栏；正文采用等宽字体和中性色，不把整段命令染为强调色或成功色 |
| 变量标签 | 常态使用中性浅底和细边框，依靠标签形状、名称和作用域辨认；不因内容是变量就持续着色 |
| 待填变量摘要 | 中性标签底色；全局字色橙色、局部蓝色，显示组/步骤命名空间，不附加“定位”和箭头。长名称换行，键盘焦点可见 |
| 右侧变量面板 | 背景、名称、默认值、已应用值及本次输入保持中性。局部标记缺值、未应用和错误，文字明确状态 |
| 左侧步骤导航 | 状态条表达完成/失败/跳过等结果；当前执行位置用独立小标记。当前阅读行使用中性背景或边框，不能覆盖执行状态色 |
| 按钮 | “完成并下一步”“完成并结束”“应用更改”等本区域主动作使用强调色实心；复制、记录失败使用中性描边；跳过使用轻量文字样式 |
| 编辑与焦点 | 悬停使用中性层次变化；焦点环与选中控件可使用强调色。键盘焦点始终可见，不能仅靠悬停发现入口 |
| 历史与只读内容 | 保持正常阅读对比度，辅以只读/锁定文字或图标；不把整块历史内容按禁用控件整体降低透明度 |
| 保存状态与反馈 | 稳定的“已保存”可保持中性；保存中、未提交、失败分别用文字说明。短暂成功提示可以局部使用成功语义色 |

当前执行位置、当前阅读位置、最近一次执行结果是三个不同维度。失败后仍停留当前步骤时，可同时显示当前执行小标记和失败状态条；不得为了表示“当前”把失败结果覆盖成强调色，也不得因为回看历史将其误标成当前执行步骤。

## 浅色与暗夜的层次

- 浅色：白色主内容区，中性浅灰工具栏/命令区，深灰正文和较浅分隔线。侧栏不再使用大面积深绿色。
- 暗夜：中性深灰主背景，输入框、菜单和命令区用适度亮度差形成层次，正文为清晰的浅色。禁用荧光、渐变和大面积彩色底。
- 两套主题使用相同的语义令牌，根据各自背景配置对比度；不以整体反色代替暗夜设计。
- 成功、注意、失败在两套主题中保持含义，通过适合各自背景的文字/图标/边框组合表达，不直接复用同一套色值。
- 变量草稿、当前步骤、历史冻结、复制内容和执行状态不因主题变化而改变。

## 排版与控件

- UI 采用现有系统无衬线字体；命令使用等宽字体。标题层级依靠字号、字重和间距，不依靠彩色标题。
- 同级按钮和单行输入统一高度、圆角及基线；紧凑命令工具栏使用明确的紧凑尺寸，避免每个控件独立微调。
- 图标沿用现有线性图标体系，常态跟随文字颜色；危险、状态和焦点位置按对应语义使用颜色。
- 减少重复边框和装饰性底色，优先保留帮助辨认输入区、命令卡、分组及结果的边界。命中区域、留白和实际交互位置不随视觉减法缩小或迁移。

## 实现入口与令牌分层

当前入口 `apps/desktop/src/main.tsx` 加载清单版 `ChecklistApp`，其样式以 `apps/desktop/src/checklist/checklist.css` 及下列专项样式为准。旧版 `apps/desktop/src/styles.css` 不作为当前主题改造入口。

| 样式文件 | 改造关注点 |
| --- | --- |
| `checklist.css` | 基础表面、文字、控件、窗口、列表、步骤/组、命令、结果与对话框 |
| `variable-panel.css` | 右侧面板、搜索、作用域、定义表单、值及草稿提示 |
| `step-navigation.css` | 中性目录、执行位置/阅读位置、结果状态和预览 |
| `inline-editing.css` | 原位编辑、空占位、悬停、焦点和只读 |
| `selection-tools.css` | 选区浮动入口与变量弹层 |
| `slash-menu.css` | 变量候选、普通悬停与明确选中 |

令牌按职责分层，组件只消费语义角色：

- 表面：工作区、侧栏/工具栏、卡片、输入、浮层。
- 文字：主文字、次文字、占位、禁用文字、强调底上的文字。
- 边界：分隔、输入边框、悬停、焦点、只读边界。
- 强调：主要操作常态/悬停/按下、轻选中背景、当前执行标记。
- 语义：成功、注意、失败、危险，各自包含需要的文字、背景和边框角色。

原硬编码颜色已迁移为同一组角色；`theme.css` 集中维护两套色值，各组件消费语义令牌，不通过末尾追加整套覆盖制作第二主题。主题属于应用显示偏好，不加入模板、实例、执行快照或 JSON/ZIP 业务存档。

## 实施顺序与验收

1. 先统一颜色令牌与主要控件，完成中性浅色基础。
2. 清理标题、命令、变量、侧栏及步骤组的大面积/常驻绿色，区分强调与结果。
3. 以同一组语义角色实现中性暗夜，细化切换入口与本地偏好。
4. 检查正常、悬停、焦点、按下、禁用、只读、缺值、未应用、失败和成功等状态，修正对比度及布局。

验收覆盖模板/块/当前/归档列表、编辑与执行、右侧变量、选区及变量候选菜单、左右步骤菜单、结果历史、评论图片、导入/删除/终止对话框、一体化窗口按钮及保存反馈。浅色/暗夜分别检查宽窄内容视口、长步骤、键盘焦点与文字/图标/边框对比度。

必须保持现有菜单位置、当前执行与阅读位置分离、参数显式应用、历史冻结、独立副本和关闭保护；仅切换主题不得修改业务数据。完成后更新独立桌面端并进行隔离交互回归，验证完成前不把本规范标记为已实现。
